# Day 6 — Logistic-regression baseline

## Objective

Establish a simple, reproducible classification baseline from the Day 5 pot-date spectral table. This is an observed-date classification experiment, not a temporal forecasting experiment.

## Input contract

The input is `pot_date_spectra.csv` generated by `scripts/explore_spectra.py`. It must contain:

- At least two numeric `band_NNN` columns.
- A verified pot grouping key (default `pot_id_candidate`).
- A verified acquisition date (default `date_folder_yyyymmdd_candidate`).
- A verified target label joined from the actual annotation schema.
- Exactly one row per pot at the selected date.

The selected date is mandatory and must be fixed before model evaluation. The script refuses duplicate pot rows, missing labels, missing groups, all-missing spectral bands and treatment labels that change within a pot across dates.

## Target semantics

The required `--target-semantics` argument distinguishes:

- `treatment_assignment`: predicts experimental inoculation assignment. This is not symptom detection, infection onset or disease forecasting.
- `observed_infection_status`: predicts independently observed infection status at the selected date. This is same-date classification, not a future outcome.
- `symptom_severity`: predicts a same-date severity category. This is not future severity forecasting.

Do not pass the paper's inoculated/control assignment as an observed symptom label. The target's meaning must be verified from the data dictionary and experimental protocol first.

## Model and evaluation

The baseline is:

1. Median imputation.
2. Standard scaling.
3. Logistic regression with `class_weight="balanced"`, `C=1.0` and `max_iter=5000`.

These steps are assembled in a scikit-learn `Pipeline` and fitted independently inside each training fold. The script uses 5-fold `StratifiedGroupKFold`, grouping by pot. At least five independent pots per class are required. It stores the fold assignment for every pot and out-of-fold predictions.

Reported metrics include accuracy, balanced accuracy, macro-F1, macro-precision, macro-recall, class-wise precision/recall/F1, confusion matrix and binary ROC-AUC where applicable. No hyperparameter search is performed on this baseline.

The final serialized pipeline is separately fitted on all selected-date rows after out-of-fold evaluation. It is intended as a downstream demo candidate; its in-sample predictions are not used for the reported metrics.

## Leakage safeguards

- One selected acquisition date means no pot contributes multiple time points.
- Pot is the group because treatment was assigned at pot level.
- Exactly one pot-date row is required; ROI/pixel rows cannot be treated as independent samples.
- Imputation and scaling are fitted on training folds only.
- Only spectral band columns are features; pot IDs, dates, treatment and genotype metadata are not features.
- Split assignments and out-of-fold predictions are saved for audit.
- The task remains classification at time (t), not prediction of a future state at (t + \Delta).

## Run

First generate Day 5 pot-date spectra with a verified annotation join. Inspect the annotation file and use the actual target field and exact join keys; placeholders must not be copied literally.

Then run:

```bash
python scripts/train_baseline.py \
  --input-csv reports/eda/vnir/pot_date_spectra.csv \
  --output-dir models/day6_vnir \
  --target-column ACTUAL_VERIFIED_LABEL_COLUMN \
  --target-semantics treatment_assignment \
  --date-value VERIFIED_DATE_YYYYMMDD \
  --n-splits 5 \
  --random-state 42
```

Use `observed_infection_status` or `symptom_severity` only if those labels are independently measured and their meaning is documented. For a treatment-assignment baseline, explicitly state that the model discriminates experimental assignment rather than disease symptoms.

## Verification status

The implementation was tested with a synthetic two-class pot-date fixture. This validates the code path and grouped out-of-fold bookkeeping only. The actual annotation CSVs, Day 4 spectra and verified biological labels have not been run through the baseline in this execution. No real model metrics are reported.

## Day 5 regression fix

During Day 6 review, the Day 5 band-column regular expression was found to contain an escaped backslash, preventing ordinary names such as `band_001` from matching. It has been corrected to recognize numeric band suffixes. The existing Day 5 band-order test covers this behavior; a full repository test run remains outstanding.
